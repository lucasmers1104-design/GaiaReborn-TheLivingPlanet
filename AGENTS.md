## Project 
Name: Gaia Reborn – The Living Planet² (formerly "SimEarth 2.0" / working title earthsim; renamed 2026-10-22, internal ids such as the `simearth2.*` localStorage keys stay unchanged so saves keep working)
- Genre: nature and evolution sandbox, a modern successor to SimEarth: The Living Planet (Maxis, 1990)
 
- Stack: TypeScript 5.9 (`strict`, target ES2020), no runtime dependencies, no framework, no bundler; Canvas 2D for the pixel map (landscape: a generated 16×16 pixel-art PNG atlas); tests with `node:test` on Node 22. Use only APIs of these versions.
- Target: desktop browsers only. `index.html` must keep running straight from disk over `file://`, with no server. Input: mouse and keyboard. Only headless Chrome has been verified so far.

## Commands
- Build: `npm run build` (tsc → `simulation.js`, then `tools/stamp-version.js` writes the `package.json` version into it and `tools/wrap-bundle.js` wraps it in `function seBundle()`, the source the Blob workers start from; `npm version` rebuilds) · `npm run watch` while working (version shows as `dev`; unwrapped, so the planet runs on the page)
- Run the game for the user: build, then open `index.html` in the browser
- Typecheck: `npm run typecheck`
- Test:
  - `npm run test:quick`: core tests with short simulations (incl. coal and giant clubmosses), ~30 s; needs a current build.
  - `npm run test:full` (= `npm test`): builds, then runs every test file (~450 tests, ~40 min; founding and evolution take most of it).
  - Single file: `npm run build`, then `node --test --test-reporter=dot tests/<name>.test.js`.
  - Map look on one seed in seconds: `node tools/green-probe.js [seed]` (young rock, greening, plants drawn) and `node tools/relief-probe.js` (mountains, rock rule, tree line, rain shadow).
  - Parallel work: build to your own file (`npx tsc -p tsconfig.json --outFile <scratch>/simulation.js`, then `node tools/wrap-bundle.js <scratch>/simulation.js` for the workers) and set `SE_BUNDLE=<that file>` for tests and the probe, so the shared `simulation.js` stays untouched
- Headless probe: `npm run probe` or `node tools/headless.js [ticks] [seed …] [--life] [--timeline] [--map] [--track] [--epoch=<id>]`. Use it for tuning results that unit tests can't show (deserts, rivers, erosion, how the biosphere grows, when each step lands on the Earth calendar).
- Landscape art: `node tools/terrain-atlas.js [--check] [--sheet [dir]] [--part a,b] [--family cold|temperate|warm|wet|mountain|coast|fields] [--write]` builds every terrain texture, edge mask and plant object from the recipes in `tools/terrain/`, checks them and renders contact sheets; `--write` regenerates `assets/terrain/` and `src/terrainatlas.ts` (one writer at a time). `tests/terrain.test.js` fails while the committed atlas is stale.
- Disaster effects: `node tools/fx-atlas.js [--check] [--sheet [file]] [--write]` builds the effect sprites and animated ground textures from `tools/fx/`; `--write` (lead only) regenerates `assets/fx/` and `src/fxatlas.ts`, which `tests/fxatlas.test.js` checks. `node tools/fx-record.js --kind <id> [--x N --y N] [--zoom px] [--reduce]` records a disaster on the map (animated PNG, contact sheet, frames; headless Chrome, honours `SE_BUNDLE`). `node tools/hazard-probe.js [--kind id] [seed …]` prints reach, spread and healing times.
- Interface art (the living interface): `node tools/ui-atlas.js [--check] [--sheet [file]] [--preview [file]] [--part gaia,face,rail,topbar,vines,magic] [--family a,b] [--placeholders] [--write | --out dir]` builds Gaia, her rock, the vines, frames, rail and status-bar icons and the evolution magic from `tools/uiart/` (contract `catalog.js`, palette `palette.js` = the terrain palette plus UI ramps); `--preview` composes them (Gaia's poses on the rock with face overlays, the rail, a status-bar mock, vines, magic); `--write` (lead only) regenerates `assets/uiart/` and `src/uiatlas.ts`, which `tests/uiatlas.test.js` checks. `node tools/ui-bundle.js --out <dir>` compiles the game with the UI atlas built fresh from the recipes (parallel work; prints the bundle path). `node tools/ui-shot.js [--bundle file] [--page preview|index] [--query …] [--w N --h N --dpr N] [--eval js] [--clip x,y,w,h,scale] [--frames n --gap ms] --out <png>` takes headless-Chrome screenshots over CDP, serialized by a lock; `?magic=1` lets Gaia's magic play on preview pages.
- Earth map: `node tools/earth-map.js [etopo.asc] [--fetch] [--png <file>] [--write]` averages NOAA ETOPO1 onto the grid and regenerates `src/earthmap.ts` (the epoch "Heute").
- Dinosaurs' era: `node tools/comet-probe.js [ticksAfter] [seed …] [--survive]` plays to the first birds, answers the question and follows the recovery. `tools/headless.js` and `tools/civ-probe.js` answer it with `--dino=comet|survive`, `_preview.html` with `?dino=comet|survive|show`; without it the question stays open and the era's bars hold (the preview stops there); the simulation never answers it.
- Civilization: `node tools/civ-probe.js [civTicks] [seed …] [--epoch=<id>]` plays a planet to sentience and checks spacing, sites, settlers, peoples, epidemics, conflicts, land share and CO₂ against `docs/zivilisation-spec.md` §6 (standard set: `2500 12345 2024 99` and `2500 12345 --epoch=today`). City art: `node tools/civ-atlas.js [--check] [--sheet [dir]] [--part blocks,cities,compare] [--era <id>] [--write]` builds city blocks, yards, bridges, banners, camp shelters, flame and chimney smoke frames from `tools/civ/`; `compare` is the comparison board (camp, village, town, metropolis of every era on one site, from the atlas built in memory); `CIV_ATLAS_MEMORY=1` runs `tests/civart.test.js` against that in-memory atlas; `--write` (one writer at a time) regenerates `assets/civ/` and `src/civatlas.ts`, which `tests/civart.test.js` checks.
- Species art: `node tools/species-sheet.js <id> [--file <draft.ts>] [--out <png>]` renders a class's or plant group's icons at map size on real ground colours (headless Chrome, serialized by a lock) and prints every `PROBLEM` the art test would report. `node tools/portrait-sheet.js <id> [--file <draft.ts>] [--out <png>]` and `node tools/portraitcheck.js` do the same for the 64×64 lexicon portraits in `src/species/portraits/`.
- Space project: `node tools/space-probe.js [seed …] [--nano] [--dino=comet|survive]` plays a planet to its first Nanotech city and measures unlock, desert site, pace, phases, moves and the build time per game speed (about 10 minutes per seed); `node tools/launch-record.js [--from s] [--to s] [--at s,…] [--reduce]` records the launch film in headless Chrome (honours `SE_BUNDLE`). `_preview.html?space=<0..1>|launched&spacewin=1` shows the site in a phase.
- Intro & audio: `node tools/intro-record.js` records the intro sequence in headless Chrome; `node tools/rumble-embed.js` regenerates `src/rumblebass.ts` from `assets/audio/sfx/rumble-bass.mp3`.
- Performance: `node tools/perf-bench.js saves|systems|browser [scenario …] [--label name] [--query sim=direct] [--throttle N] [--laps N] [--repeat N] [--variants plain,ahead,zoom,both] [--paused] [--gpu off]` measures the same scenarios before and after a change (young Earth, dense biosphere, civilization, disasters, terraforming, panning/zooming, autosave; camera paths `panzoom`, `zoomsteps`, `drag`) in Node and headless Chrome at 1920×1080; results in `tmp/perf/<label>.json`. `?land=plain|ahead|zoom|both` forces the landscape prefetch and zoom pictures on or off (default: prefetch on, zoom pictures from devicePixelRatio 1.5), `?zoombudget=<MiB>` fixes their budget, `?sprites=page` rasters creature pictures on the page as before; all for measuring. Headless Chrome here rasters canvas on the GPU (`--gpu off` for software). `F3` in the game shows the live timings.
- Screenshots: `_preview.html` closes the title screen, fast-forwards a planet with a greedy evolution tree and sets `document.title = 'ready'`. Capture it with headless Chrome over the DevTools protocol. Run browser checks one at a time. Pages that drive `SE.app` synchronously (`app.tick()`, `app.world` edits) need the planet on the page: `_preview.js` pages get it by themselves, others add `?sim=direct`.

## Layout
- `src/` holds all TypeScript. Every file is one `namespace SE { … }`. `tsc` concatenates the files into one classic script, `simulation.js`, in the order of `files` in `tsconfig.json`. There are no ES modules: cross-file references go through `SE`, and a file may only use at load time what earlier files define (late-bound callbacks `driftProbe`, `civEventSink` and `hazardSink` bridge simulation systems to `SimCore` at runtime).
  - foundation & dev tools: `constants` (enums, grid geometry, `LIFE`/`TECH`/`OMEGA` tables), `util` (`Rng`, grid math, formatting, DOM helpers), `devmode` (`// DEVMODE` toggle), `perfhud` (`F3` frame/tick/chunk timing overlay)
  - species art, portraits & lore (pure data, Node-safe): `species/types.ts` (format, palette, `SPECIES_ART` & `FLORA_ART` registries), `species/<class-id>.ts` (8 sub-species + biome specialists per animal class), `species/portraits/types.ts` + `species/portraits/<class-id>.ts` (64×64 lexicon portraits per sub-species in `SPECIES_PORTRAITS`), `species/lore/types.ts` + `species/lore/<class-id>.ts` (German lexicon texts per sub-species in `SPECIES_LORE`), `floraart/<group-id>.ts` (sparse/dense cover + specialists per plant group)
  - simulation: `params` (0..1 slider state and calibration), `oxygen` (air vs. sea $\text{O}_2$ thresholds), `landscape` (landscape/substrate enums and succession tables), `calendar` (Earth eras and tick pacing), `civstate` (records beside the `tech`/`cityPop` grid), `hazardstate`, `dinoera` (the dinosaurs' era: its fate and what it bars) + `comet` (the player's choice and the strike) + `cometwinter` (the strike's ice over two thirds of the planet), `world` (`TerrainGenerator` and `WorldState` typed arrays), tectonics & relief (`tectonics` with `raiseCrust` as the single vertical crust write path, `orogeny` typed mountain belts, `breach` water gaps through new ranges, `islandarcs` trenches and volcanic arcs, `erosion` slope wear and deposition), `epochs` (start planets: random or the Earth in an epoch; ## Code
- Smallest coherent change; no unrelated edits, no full-file rewrites.
- Add comments or docstrings only for constraints or rationale the code can't express (e.g. browser quirks, measured tuning); intent goes into names and types.
- No new abstractions, wrappers or dependencies without a concrete need. No runtime dependencies, bundler or ES modules: the `file://` start must keep working.
- Never add markup to `index.html` for new UI; create it in code (`make` + append). The local server (`python -m http.server`) sends no cache headers, so the browser can pair a cached old `index.html` with a new `simulation.js`, and `el()` on a missing id stops the boot.
- One responsibility per file; put new features in new files instead of growing files past ~300 lines. Many files are already larger; keep your edits there to wiring.
- A new `.ts` file goes into `files` in `tsconfig.json`, after everything it uses at load time. A new `.css` file gets an `@import` in `styles.css`.
- Pass randomness and time into game rules so they stay testable. Simulation randomness comes from the seeded `world.rng` or a hash roll (like `spontaneousRoll`), never from `Math.random()` or `Date.now()`. `Math.random()` is fine for purely visual effects.
- Player actions (tools, evolution steps, model panels, disasters) are `SimCommand`s: `app.ts` asks `SimCore.check()` on the state it shows, then `SimCore.apply()` checks again against the planet itself (in the worker) before it changes anything; results come back with the state that contains them. Never trust UI state, and never write `app.world` from UI code: it is a mirror in worker mode.
- Balancing values (costs, rates, thresholds, tree data) live in `constants.ts`, `params.ts` and the tables in `evolution.ts`, not inline in logic. Sliders run 0..1, with 0.5 as the calibrated default.
- Player-facing text is German and lives in the code tables (`constants.ts`, `evolution.ts`, `stories-*.ts`, UI files). There is no i18n layer; don't add one unasked.
- Save format changes bump `SAVE_FORMAT` in `src/save.ts` and come with a migration from the previous format (see `migrateV4`). Old saves are read, never deleted.
- Assets are SVG, in the style of `assets/README.md`, and included via `evoIcon`, `uiIcon`, `resIcon`, `habitatAsset` and `eventIcon`. Only the map's landscape (ground, transitions, plant objects), the disaster effects, the cities and the living interface (Gaia, the vines, the status bar's and rail's frames and icons, the magic) are pixel-art PNG, generated from recipes by `tools/terrain-atlas.js`, `tools/fx-atlas.js`, `tools/civ-atlas.js` and `tools/ui-atlas.js`; never paint them by hand. Whales surfacing on the open sea at ≥ 16 px per tile are fx-atlas pixel sprites (`tools/fx/fauna.js`); further out, and all other animals and graphics, stay SVG.
- Films run 12 s in 4 beats, with `sparkle()` at 6–8 s. Show change across generations with `morph()` plus `timelapse()`, never an individual transforming. Phrase advantages as selection, never as purpose. No scripts, SMIL, filters or remote resources in SVG.
- Don't drop validation or error handling when simplifying.

## Workflow
1. Ambiguous and costly to redo? Ask first; when running unattended, pick the most reasonable reading and state it.
2. Before changing shared code, types, method names or data formats, find all references. That includes string references in tests, `tools/headless.js`, `_preview.js`, CSS class names and asset filenames (node ids are filenames).
3. Build, then run focused checks: `npm run typecheck`, `npm run test:quick` or the affected test files. Run `npm run test:full` once, before finishing a larger change, and don't rebuild `simulation.js` while it runs.
   - Never pull whole test logs into context. Redirect to a file and show only the summary and the failing tests (`--test-reporter=dot`, `grep`, `tail`).
   - Reproduce a bug with the shortest run that shows it (one seed, few ticks, a probe) before running suites. Check tuning with the headless probe and UI with a headless-Chrome screenshot. Report what ran, what didn't, and what needs manual playtesting (other browsers, real touch devices, sound).
4. Update docs only where facts changed: the matching German report in `docs/`. Never document what code or tooling already shows.

## Git
- Remote: `origin` = https://github.com/DreamstudiosGit/earthsim, default branch `main`.
- Commit or push only when the user asks; then always run `node scripts/ship.mjs "<type>(<scope>): <summary>"`. Never commit or push with plain `git`, which skips the checks.
  - It builds and runs the quick tests (`--full`: the whole suite), releases a new version, logs to `docs/done.md`, commits all changes, tags the version, pushes to `origin` and opens a PR from non-main branches (needs `gh`; otherwise it prints the compare link).
  - Every commit is a new version: `version` in `package.json` (and the lockfile), tag `v<version>`, and the version at the end of the commit subject and in `docs/done.md`. The patch number goes up by one (0.6.0 → 0.6.1); `--minor` → 0.7.0, `--major` → 1.0.0. A version set by hand (`npm version <x.y.z> --no-git-tag-version`) is released as is while it has no tag. Never change versions or tags any other way.
  - `--dry-run` runs the checks and lists what would be committed as which version. Further quoted arguments become body paragraphs of the commit message.
  - type: `feat|fix|perf|refactor|style|test|docs|build|chore`; scope: the area touched, e.g. `evolution`, `flora`, `climate`, `save`, `map`, `ui`, `films`, `assets`, `docs`, `tools`.
- Never discard changes you didn't make.
